## Findings considered and rejected

- Replacing the current JSON solely to repair a fixed-temporary-file race was
  rejected as the justification: the implementation already uses a GUID temp
  path and a Linux inter-process lock. SQLite remains worthwhile for
  transactional state transitions, crash recovery, scalable queries, and
  verifiable multi-process concurrency. It is designed as Lutra's application
  database (`lutra.db` under the application state directory), with backup
  history as its first repository rather than as the database boundary. The
  DB remains local operational state and is deliberately excluded from sync,
  bundles, and automatic snapshots.
